# 周易记忆卡 — MVP (v1.0) 产品需求文档

## 1. 产品概述

**产品名称**：周易记忆卡（ZhouYi Memory）

**一句话描述**：用间隔重复（Spaced Repetition）帮助用户记忆周易六十四卦的基础知识。

**目标用户**：对周易感兴趣、希望系统记忆六十四卦基本信息的学习者。

**核心价值**：把枯燥的死记硬背变成科学的间隔复习，让用户在碎片时间里高效掌握六十四卦。

## 2. 技术方案

| 项目 | 选型 |
|------|------|
| 框架 | React 18 + TypeScript |
| 构建 | Vite |
| 样式 | Tailwind CSS |
| 部署 | PWA（可离线使用，可添加到主屏幕） |
| 数据存储 | 浏览器本地存储（localStorage / IndexedDB） |
| 记忆算法 | SM-2 |
| 后端 | 无（纯前端，MVP 不需要服务器） |

## 3. 内容范围

MVP 仅覆盖 **六十四卦的基础信息**：

| 字段 | 说明 | 示例 |
|------|------|------|
| 卦象 | Unicode 卦象符号 | ☰ |
| 卦名 | 卦的名称 | 乾 |
| 卦辞 | 卦的原文辞句 | 元亨利贞 |
| 上卦 | 组成该卦的上经卦 | 乾（天） |
| 下卦 | 组成该卦的下经卦 | 乾（天） |

> MVP **不包含**：爻辞、彖传、象传、序卦传等扩展内容。

## 4. 卡片类型

MVP 包含 3 种卡片类型：

### 类型 A：卦象 → 卦名

- **正面**：显示卦象符号（如 ☰）
- **背面**：卦名（如「乾」）
- **考察能力**：看到卦象能说出卦名

### 类型 C：卦名 → 卦辞

- **正面**：卦名（如「乾」）
- **背面**：卦辞（如「元亨利贞」）
- **考察能力**：看到卦名能回忆卦辞

### 类型 G：卦象 → 上下卦构成

- **正面**：六爻卦象符号（如 ䷀）
- **背面**：上卦 + 下卦（如「上乾下乾」）
- **考察能力**：看到复合卦象能分解出上下经卦

> 每卦最多生成 3 张卡片，64 卦共 **最多 192 张卡片**。

## 5. 学习模式

### 5.1 翻卡片模式（Flip Card）

1. 显示卡片正面
2. 用户心中回忆答案
3. 点击「翻转」查看背面
4. 用户自评（3 个按钮，减少决策疲劳）：
   - **不会**（Again） → quality = 1（完全没想起来）
   - **想起来了**（Good） → quality = 3（想起来了但费劲）
   - **很简单**（Easy） → quality = 5（秒答，毫不费力）

> 为什么是 3 个按钮而不是 4 个？用户在翻卡后还要做一次"我到底记得多好"的心理判断，选项越少决策越快，学习体验越流畅。3 档（不会 / 勉强 / 轻松）已足够驱动 SM-2 算法。

### 5.2 四选一模式（Quiz）

1. 显示卡片正面
2. 给出 4 个选项（1 个正确 + 3 个干扰项）
3. 用户选择答案
4. 显示正确/错误反馈
5. 自动评分：
   - 选错 → quality = 1（用户参与了但答错）
   - 选对 → quality = 4（识别比主动回忆容易，不给满分）

#### 干扰项生成规则

- 干扰项从**全部 64 卦**中随机抽取，不限于用户已学过的卦
- 这意味着第一张新卡就能使用四选一模式，无冷启动问题
- 抽取后校验：干扰项的显示文本不能与正确答案相同（防碰撞）
- 4 个选项的显示顺序随机打乱，正确答案不固定位置

> 两种模式用户可随时切换，不影响学习进度。

## 6. 学习流程

### 核心原则：打开就学，随时可停

```
用户打开 App
  → 有到期复习卡？→ 出复习卡
  → 复习卡做完 / 没有复习卡？→ 出新卡片
  → 用户随时可停，下次继续
```

### 详细流程

1. **进入首页**：显示简洁的学习入口 + 当前学习统计概览
2. **点击「开始学习」**：进入学习 session
3. **出卡逻辑**（优先级从高到低）：
   - 已学过且到期需复习的卡片（按到期时间排序）
   - 未学过的新卡片（按卦序排列）
4. **单张卡片流程**：展示 → 作答 → 反馈 → SM-2 更新 → **立即保存** → 下一张
5. **结束 session**：
   - 用户主动点「结束」退出
   - 或当前无更多到期卡片且用户不想学新卡
6. **Session 结束页**：展示本次学习统计（复习了几张、学了几张新的、正确率）

### 学习进度显示

学习过程中，顶部始终显示全局进度信息：

```
已掌握 42/192 · 今日待复习 8 · 新卡 5
```

- **已掌握 X/192**：repetitions ≥ 1 的卡片数 / 总卡片数
- **今日待复习**：dueDate ≤ today 且已学过的卡片数
- **新卡**：本次 session 已学的新卡数量

### 新卡节奏控制

每次 session 默认学习 **5 张新卡**后弹出提示：

> 「今天已学 5 张新卡，建议先到这里，明天复习后再学新的」
> ［继续学新卡］ ［结束学习］

- 这是**软限制**，不是硬墙，用户可以选择继续
- 目的：防止用户第一天学完 192 张，第二天面对 192 张复习卡的「雪崩」
- 每次继续后再学 5 张会再次提示
- 此限制不影响复习卡的数量，到期的复习卡全部展示

### 答错卡片重新出现

当用户答错一张卡（quality < 3）时：

1. SM-2 状态**立即更新并保存**（重置 repetitions = 0，interval = 1）
2. 该卡片放回当前 session 队列尾部（约 3-5 张后重新出现）
3. 重新出现时的作答**不再更新 SM-2 状态**，仅作为当次强化
4. 这样既有即时巩固效果，又不会因为重做答对而意外推高间隔

### 逐卡保存

- 每答完一张卡立即将状态写入 localStorage
- 不做 session 级别的批量保存
- 原因：用户随时可能关闭浏览器/切换 App，逐卡保存确保零进度丢失
- localStorage 写入同步执行，对 ~40KB 数据量无性能影响

### 「全部完成」空状态

当所有到期卡片复习完毕且无新卡（或用户选择不学新卡）时，显示：

```
✅ 今日复习已完成！

下次复习：明天 3 张到期
总进度：已掌握 128 / 192 张卡片
```

- 必须告诉用户「下次什么时候需要回来」
- 显示总体进度，给予成就感
- 不能显示空白页，否则用户以为 App 出了 bug

### 不做的事

- ~~每日目标设定~~
- ~~打卡/连续天数~~
- ~~强制学习数量~~

## 7. SM-2 算法规格

每张卡片维护以下状态：

```typescript
interface CardState {
  cardId: string;          // 卡片唯一标识
  easeFactor: number;      // 难度因子，初始 2.5
  interval: number;        // 当前间隔（天）
  repetitions: number;     // 连续正确次数
  dueDate: string;         // 下次复习日期 (YYYY-MM-DD 本地时间)
  lastReviewDate: string;  // 上次复习日期 (YYYY-MM-DD 本地时间)
}
```

### 算法逻辑

```
输入: quality (1 或 3 或 4 或 5，取决于学习模式)

if quality < 3:
  repetitions = 0
  interval = 1
else:
  if repetitions == 0: interval = 1
  elif repetitions == 1: interval = 6
  else: interval = round(interval * easeFactor)
  repetitions += 1

easeFactor = max(1.3, easeFactor + (0.1 - (5 - quality) * (0.08 + (5 - quality) * 0.02)))
dueDate = today + interval 天
```

### 参数边界

| 参数 | 下限 | 上限 | 说明 |
|------|------|------|------|
| easeFactor | 1.3 | 不设上限 | 每次计算后 clamp：`Math.max(1.3, ef)` |
| interval | 1 天 | 365 天 | `Math.max(1, Math.min(365, interval))`，保证每张卡至少每年复习一次 |
| quality | 1 | 5 | 翻卡模式：1/3/5；四选一模式：1/4 |

### 过期卡片处理

用户可能多天不打开 App，导致卡片严重过期（如 interval=5 的卡过期了 25 天）。

**规则**：答对后计算下次间隔时，使用**原计划的 interval**（而非实际过去的天数）作为基数。

```
// 正确做法
nextInterval = round(scheduledInterval * easeFactor)

// 错误做法（会导致间隔爆炸）
nextInterval = round(actualElapsedDays * easeFactor)
```

这样做保守但安全，避免过期卡一次答对就跳到几个月后。

### 答错不重置 easeFactor

答错时（quality < 3）：
- **重置** repetitions = 0 和 interval = 1
- **不重置** easeFactor（保留当前值）

原因：一次失误就抹掉所有 easeFactor 积累，对用户惩罚过重。

## 8. 数据模型

### 8.1 卦数据（静态，内置于代码中）

```typescript
interface Hexagram {
  id: number;              // 1-64，按卦序
  name: string;            // 卦名，如「乾」
  symbol: string;          // 六爻卦象 Unicode，如「䷀」
  trigram: string;         // 八卦卦象（仅八经卦），如「☰」
  judgment: string;        // 卦辞
  upperTrigram: string;    // 上卦名称
  lowerTrigram: string;    // 下卦名称
}
```

### 8.2 学习记录（动态，存储在本地）

```typescript
interface StudyRecord {
  schemaVersion: number;                   // 数据版本号，初始为 1
  cardStates: Record<string, CardState>;   // cardId → 卡片状态
  totalReviews: number;                    // 累计复习次数
  lastStudyDate: string;                   // 上次学习日期 (YYYY-MM-DD)
}
```

### 日期格式

- 所有日期统一使用 **`YYYY-MM-DD` 本地时间字符串**（如 `"2026-02-18"`）
- **不使用** ISO 8601 UTC 时间戳（纯前端 App 没有服务器，用 UTC 反而引入时区换算问题）
- 判断到期：`dueDate <= today`，用字符串比较即可（YYYY-MM-DD 天然支持字典序比较）
- 获取今天：`new Date().toLocaleDateString('en-CA')` → `"2026-02-18"`
- 日界线：本地午夜 00:00:00

### Schema 版本管理

```typescript
// 启动时检查并迁移
function loadData(): StudyRecord {
  const raw = localStorage.getItem('studyRecord');
  if (!raw) return createDefaultRecord();

  let data = JSON.parse(raw);
  if (data.schemaVersion === 1) { /* 当前版本，无需迁移 */ }
  // 未来: if (data.schemaVersion === 1) { data = migrateV1toV2(data); }
  return data;
}
```

初始版本为 1，后续每次改变数据结构时递增版本号，编写对应的迁移函数。

### 存储方案

- 使用 `localStorage`，单一 key `studyRecord` 原子写入
- 192 张卡片 × ~200 bytes ≈ 40KB，远低于 localStorage 5MB 限制
- 不存储逐次复习历史记录（只保存卡片当前状态）
- MVP 不做云同步、不做导入导出

### 存储安全措施

1. **所有 `JSON.parse` 包裹 try/catch**：解析失败视为数据损坏，重置为全新状态并提示用户
2. **所有 `localStorage.setItem` 包裹 try/catch**：捕获 `QuotaExceededError`
3. **隐私浏览检测**：启动时写入/删除一个测试 key，失败则显示持久横幅：「您正在使用隐私浏览模式，关闭窗口后学习进度将丢失」
4. **原子写入**：整个状态序列化为一个 JSON 写入单一 key，不拆分多个 key，避免半写状态
5. **数据损坏恢复**：如检测到 `schemaVersion` 缺失或数据结构异常，清除并重新初始化，显示：「学习数据异常，已重置。」

## 9. 页面结构

MVP 只需 **3 个页面**：

### 9.1 首页（Home）

- 学习入口按钮「开始学习」
- 统计概览：已学卡片数 / 总数、今日待复习数
- 模式切换（翻卡片 / 四选一）

### 9.2 学习页（Study）

- 卡片展示区域
- 翻卡片模式：翻转动画 + 3 个自评按钮（不会 / 想起来了 / 很简单）
- 四选一模式：4 个选项按钮 + 正确/错误反馈
- **顶部全局进度**：`已掌握 42/192 · 今日待复习 8 · 新卡 5`
- 「结束学习」按钮
- 卡片文本区域设置 `overflow-y: auto`，适配长卦辞文本

### 9.3 学习完成页（Summary）

两种情况：

**A. Session 结束（用户主动点结束 / 到期卡复习完毕）**
- 本次学习统计：复习卡片数、新学卡片数、正确率
- 「返回首页」按钮

**B. 全部完成空状态（无到期卡且无新卡可学）**
- 下次复习时间：「明天 3 张到期」
- 总进度：「已掌握 128 / 192 张卡片」
- 「返回首页」按钮

## 10. 非功能需求

| 项目 | 要求 |
|------|------|
| 离线可用 | PWA Service Worker 缓存，断网可正常使用 |
| 响应式 | 移动端优先，同时适配桌面端 |
| 性能 | 首屏加载 < 2s，卡片翻转无卡顿 |
| 数据安全 | 本地存储，提醒用户清除浏览器数据会丢失进度 |
| 浏览器支持 | Chrome / Safari / Firefox 最近 2 个主版本 |

### PWA 策略

- **缓存策略**：Stale-while-revalidate — 先用缓存快速展示，后台检查更新
- **更新提示**：检测到新版本后，显示非阻塞横幅：「有新版本可用，点击更新」，用户点击后 `location.reload()`
- **缓存版本号**：使用 `CACHE_NAME = 'zhouyi-v1'`，更新时换版本号，在 `activate` 事件中清除旧缓存
- **预缓存范围**：App shell + 卦数据（JSON/JS），全部静态资源，总计 < 1MB
- **内容缓存失效**：卦数据文件名包含内容 hash（如 `hexagrams.a3f8b2.js`），内容变化 → 文件名变化 → 自动失效

### Unicode 卦象符号渲染

- 六十四卦使用 Unicode Yijing Hexagram Symbols（U+4DC0–U+4DFF）
- 八经卦使用 Miscellaneous Symbols（☰ ☱ ☲ ☳ ☴ ☵ ☶ ☷）
- 字体回退栈：`"Segoe UI Symbol", "Apple Symbols", "Noto Sans Symbols2", "DejaVu Sans", sans-serif`
- 如个别设备无法渲染，后续可用 CSS 绘制六爻线条作为 fallback（MVP 暂不实现）

## 11. 边界情况与技术决策

### 11.1 Session 中断与恢复

**场景**：用户复习了 10/30 张到期卡后关闭浏览器。

**处理**：不持久化 session 状态。下次打开 App 重新计算队列 — 已复习的 10 张已逐卡保存（不再到期），剩余 20 张仍到期，自然出现在新队列中。

### 11.2 卡片类型交叉出现

**场景**：同一卦的 A/C/G 三张卡同时到期，连续出现会互相提供线索。

**处理**：对 session 队列做随机 shuffle。大多数时候不同卦的卡片自然交错；极端情况（少量卡片到期）可接受。

### 11.3 卦辞文本长度差异

**场景**：有的卦辞极短（「元亨利贞」4 字），有的较长（数十字）。

**处理**：
- 翻卡模式：卡片文本区域 `overflow-y: auto` + `max-height: 60vh`
- 四选一模式：选项文本超过 80 字符时截断显示省略号，答题后展示完整文本
- 用乾卦（短）和既济卦（长）作为 UI 测试用例

### 11.4 多标签页同时打开

**场景**：用户在两个标签页同时学习，数据写入冲突。

**处理**：MVP 不处理。数据丢失范围极小（一张卡的状态），场景罕见。后续可监听 `storage` 事件做跨标签同步。

### 11.5 时区变化

**场景**：用户跨时区旅行，本地午夜时间偏移。

**处理**：MVP 不处理。使用本地时间意味着行为始终与用户当前时区一致，最多导致某张卡提前/推迟一天到期，对间隔重复影响可忽略。

### 11.6 设备时钟篡改

**场景**：用户手动调整设备时间以提前查看卡片或逃避复习。

**处理**：MVP 不处理。这是个人学习工具，没有竞争/社交机制，用户只影响自己。
